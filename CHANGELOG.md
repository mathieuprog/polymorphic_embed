# Changelog

## Unreleased

  **Breaking changes**:

  * `nil` for a list of embeds gives the error "is invalid", as in Ecto. Before, the cast
    ignored it.
  * With `required: true`, `changeset.required` contains the field, and an empty list in
    the data gives "can't be blank", as in Ecto.
  * An invalid `:on_replace` option raises `ArgumentError`, not `RuntimeError`.
  * After the cast, `changeset.params` holds the params of each child for the field. For a
    list of embeds, it is a list in the order of the cast, without dropped and ignored rows.
  * The form of an invalid child takes its params from the child changeset, as in
    phoenix_ecto. Before, it took the params of the parent by index. When a `with:` function
    builds the changeset without `cast/4`, the changeset has no params, and the form gets
    `%{}`. Use `cast/4` in a `with:` function, so that the form keeps the params of the row.
  * The hidden inputs of a child form hold the primary key of a row that the data holds,
    as in phoenix_ecto, so the form sends the id back.

  **Fixes**:

  * Params that are not maps give the error "is invalid", as in Ecto. Before, the cast
    crashed.
  * A list of embeds matches the rows of the data by primary key, as in Ecto. Before, params
    with string keys matched no row, so each row got a new id and lost the data that the
    params did not set.
  * An embedded schema with an autogenerated integer id no longer crashes the cast.
    `dump/3` raises the same `ArgumentError` as Ecto when the id is still `nil` on insert.
  * Each child form of a list gets the params of its own row. Before, the first form got
    the params of all rows.
  * A child form takes the action of the parent form, so it shows the errors of an invalid
    child, and `form.data` is the data of the child, not a changeset.
  * `get_polymorphic_type/2` of the HTML helpers reads the type from the cast data first,
    then from the input value. Before, it returned `nil` for a nested embed when the params
    had no type key, for example with `:use_parent_field_for_type`.

  `form[:field].value` gives the value for an input: the change, else the param, else the
  data. For a nested embed of a child form, read the data with
  `Ecto.Changeset.get_field(form.source, field)`.

## 5.0.2

  * Remove warning when aliases cannot be expanded (#123).

## 5.0.1

  * Relax `phoenix_live_view` constraint to allow 1.0.

## 5.0.x

  * Fix usage with Ecto 3.12. Require Ecto 3.12 or later
  * Allow inferring type from parent field via new :use_parent_field_for_type option

## 4.1.x

  * Add `Form.source_data/1` and `Form.source_module/1` (`get_polymorphic_type/2` doesn't work for list of embeds)
  * Add `:retain_unlisted_types_on_load` and `:nilify_unlisted_types_on_load` options
  * MongoDB fix
  * Deprecate `:type_field` in favor of `:type_field_name`

## 4.0.x

  * Support `sort_param` and `drop_param` for list of embeds
  * Add `PolymorphicEmbed.HTML.Component.polymorphic_embed_inputs_for/1`
    (similar to `Phoenix.Component.inputs_for/1`)
  * Support updating list of embeds while retaining ids
  * Fix form input rendering for list of embeds
  * Fix `traverse_errors` for nested embeds

  **Breaking Change**: The form helper `get_polymorphic_type/3` has been updated to `get_polymorphic_type/2`.
  The module name parameter (previously the second parameter) has been removed.

## 3.0.x

  * Default value for polymorphic list of embeds is `[]` instead of `nil` (following `embeds_many/3`)
  * Support Phoenix HTML 4.0
  * Avoid compile-time dependencies between parent and polymorphic embedded schemas

### Migration from 2.x to 3.x

  * Use `polymorphic_embeds_one/2` and `polymorphic_embeds_many/2` macros instead of `field/3`

## 2.0.x

  * Support IDs

### Migration from 1.x to 2.x

  * Make sure that every existing polymorphic `embedded_schema` contains the setting `@primary_key false`

## 1.10.x

    needing to specify the type
